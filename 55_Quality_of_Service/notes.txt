Introduction:
    - Providing a better quality to certain applications at the detriment of other applications
    - Introducing unfairness into the network
    - Traffic Types:
        - Data : 
            - Bursty
            - Greedy (tries to grab as much bandwidth as they can)
            - Sometimes it is opposite to the above two - smooth and benign
            - Drop insensitive (If a packet is dropped, does not matter because it it retransmitted); ex. TCP
            - Delay Insensitive
            - Two Major Categories : 
                - Interactive
                - Non interactive
        - Voice:
            - Smooth
            - Bening (Voice codecs like G729 and G711 requires a certain amount of bandwidth and they need that for the entire voice call)
            - Drop sensitive (if dropped, will affect the voice conversations)
            - Delay sensitive (if delayed, will affect the voice conversations)
            - Transferred via UDP
            - Requirements (One way):
                - Latency < 150 ms
                - Jitter < 30 ms
                - Loss < 1%
                - Bandwidth (30-128 kbps)
        - Video:
            - Bursty
            - Greedy
            - Bandwidth directly proportional to the movement
            - Drop sensitive
            - Delay sensitive
            - UDP
            - Requirements (One way):
                - Latency < 150 ms
                - Jitter < 30 ms
                - Loss < 0.1-1%
                - Bandwidth (384 kbps -20+ mbps)
    - Voice and Video is Prioritized above non-delay sensitive applications such as FTP
    - Hence we implement policies and mechanisms on a network to prioritize certain traffic types over other traffic types

Trust Boundary:
    - Untrusted Domain
        - Part of the network that you are not managing 
    - Trusted Domain
        - Part of the network that only administrators can manage

Policers:
    - Performs checks for traffic violations against a configured rate
    - Do not delay the traffic

Shapers:
    - Does not drop the traffic but smooth it by delaying the traffic 
    - Are usually used to meet Service Level Agreements
    - Happens when the traffic spikes above the contracted rate
    - Excess traffic is buffered

Queuing:
    - FIFO (First In First Out):
        - A single queue with packets that are sent in the exact order they arrived
    - PQ (Priority Queue):
        - Consists of four queue's that are served in a strict priority order
        - The lower priority queues are served only when the higher-priority queues are empty
        - Ranked as per - High, Medium, Normal, Low
        - Classification can be done based on the protocols and lower priority queues can be starved by the higher priority queues
    - CQ (Custom Queuing):
        - 16 queues are serviced in a round robin fashion
        - In order to prevent starvation
        - It provides traffic guarantees
        - Does not provide strict priority for real time traffic
        - Introduces delay, for ex., if you have important voice traffic arriving it will be serviced in its round
    - WFQ (Weighted Fair Queuing )
        - Algorithm that divides ethernet bandwidth by the number of flows
        - It provides a good service for real-time traffic
        - No bandwidth guarantees for particular flows
        - Gives preferences to smaller packets over larger packets
        - Does not provide Bandhwidth guarantees
    - CBWFQ (Class-Based Weighted Fair Queuing):
        - Traffic classes get fair bandwidth guarantees
        - Guarantees minimum bandwidth to each and every protocol - HTTP, FTP, Voice, Video, etc
        - No latency guarantees
        - Suitable for Data Networks
    - LLQ (Low Latency Queuing):
        - Takes the previous model (CBWFQ)
        - Adds a queue with strict priority (for real-time traffic)
        - While Minimum bandwidth is guaranteed, it also exercise strict policing for higher bandwidth Data
        - Suitable for Voice data
