- The primary purpose of a Spanning tree is to stop loops in a switch environments
- It was originally developed for bridges (software) and not switches (hardware)


- Types of Spanning Tree: 
    - IEEE 802.1ID :
        - The legacy standard of Spanning Tree
        - Started when Bridges were around
    - CST :
        - Assumes that there is one Spanning Tree Instance for the entire bridged network
    - PVST :
        - Only supported ISL
    - PVST* :
        - Supports ISL and 802.1Q
        - Cisco enhancement of Spanning Tree that provides a separate 802.1D Spanning Tree Instance
    - 802.1S:
        - Two spanning tree instance 
        - First instance: 1-100 (ex.)
        - Second Instance: 101-200 (ex.)
    - RSTP: 
        - Improves convergence over the 1998 version of Spanning Tree
            - Roles to ports
            - Enhancing BPDUs exchanges
        - Much quicker convergence
        - Only supports a single instance of Spanning Tree
    - Rapid PVST+
        - One Spanning tree per VLAN, but have rapid convergence
        - Can handle upto 10 VLANs really well


- MSTP is a process of mapping Multiple VLANs to the same Spanning Tree Instance

Requirements for a Spanning Tree:
    - There will be a lot of Mac Address Instability in the Mac Address Table if we are using multiple links to connect two switches (for the purpose of reliability)

BPDUs:  
    - Sent by default every 2 seconds
    - Contains lots of Information about the spanning tree
        - Bridge ID:
            - 8 Byte Value unique to the switch
            - 2 Byte Priority field
            - 6 Byte system ID
            - This is unique 
    - Types of BPDUs:
        - Configuration BPDU:
            - Used by Spanning Tree to provide information to switches
        - Topology change BPDU:
            - To tell switches of a change
        - Acknowledgement BPDU:
            - Used to confirm the receipt of a topology change in a notification

- Selection of Root Ports and Designated Ports:
    - Spanning Tree protocol follows a heirarchy of selection: 
        - Root Bridge:
            - Switch with the lowest Bridge ID (BID)
            - It is a combination of a configurable priority value and the switch's MAC address
            - Once root bridge is elected, all of its ports becomes designated ports
        - Root Port:
            - Every non-root switch must choose exactly one root port. 
            - This is the port that provides the lowest cost path back to the root bridge
            - Tie Breakers (Selection):
                - 1. Lowest Cost path
                - 2. Lowest Neighbor Bridge ID
                - 3. Lowest Neighbor Port Priority
                - 4. Lowest Neighbor Port ID
        - Designated Ports
            - Part of the Root Bridge
            - On every network segment, One port must be elected as the designated port
            - This is the port responsible for forwarding traffic from that segment toward the root bridge
            - Tie Breakers (Selection):
                - Lowest Root Path Cost
                - Lowest Bridge ID (BID)
                - Lowest Port ID


- PVST + Extended Bridge ID:
    - Creates an instance on a per VLAN basis and the Vendor would need to assign a MAC address on a per VLAN basis
    - Hence different MAC address would have to be allocated for every VLAN
    - Not recommended if there are 100s of VLANs
    - Bridge Priority (set manually) is now 4 bits, Extended System ID (VLAN) is now 12 bits (total 2 Bytes) and MAC address is now 6 Bytes and in total is 8 Bytes

- Portfast Port:
    - It is a configuration which is applied to a switch port that allows it to bypass the standard STP listening and learning states and move immediately to the forwarding state
    - It is only setup for edge devices like workstations, printers, servers, IP cameras
    - Not to be enabled with a switch, bridge or hub since it carries the risk of an instantaneous switching loop, which can bring down the entire network before STP even realizes what happened
    - Hence Port Fast is the standard best practice for the access layer and ensures a seamless user experience.
    - BPDU guard is also enabled as a standard practice, such that switches are not configured as a Portfast Port by mistake

- Blocking Ports:
    - Forward Data Frames : No
    - Learns MACs Based on received Frames : No
    - Transitory or Stable State : Stable

- Listening Ports:
    - Forward Data Frames : No
    - Learns MACs Based on received Frames : No
    - Transitory or Stable State : Transitory

- Learning Ports:
    - Forward Data Frames : No
    - Learns MACs Based on received Frames : Yes
    - Transitory or Stable State : Transitory

- Forwarding Ports:
    - Forward Data Frames : Yes
    - Learns MACs Based on received Frames : Yes
    - Transitory or Stable State : Stable

- Forwarding Ports:
    - Forward Data Frames : No
    - Learns MACs Based on received Frames : No
    - Transitory or Stable State : Stable

- Rapid Spanning Tree converges much faster than a Spanning Tree

Types of Spanning Trees:
    - STP:
        - Standards: 802.1D
        - Resource Needed: Low
        - Convergence: Slow
        - Number of Trees: One
    - PVST+:
        - Standards: Cisco
        - Resource Needed: High
        - Convergence: Slow
        - Number of Trees: One for every VLAN
    - RSTP:
        - Standards: 802.1w
        - Resource Needed: Medium
        - Convergence: Fast
        - Number of Trees: One
    - Rapid PVST+:
        - Standards: Cisco
        - Resource Needed: Very High
        - Convergence: Fast
        - Number of Trees: One for every VLAN
    - MSTP:
        - Standards: 802.1s, Cisco
        - Resource Needed: Medium or High
        - Convergence: Fast
        - Number of Trees: One for every Multiple VLANs
